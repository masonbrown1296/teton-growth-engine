Teton Growth Engine

Conference-to-pipeline system that processes operator intelligence and multi-channel engagement signals to produce personalized campaign assets.

What This Is

A working prototype of the growth engine logic layer. It takes real operator research and simulated multi-channel engagement data as inputs, runs them through a brand and messaging layer, and produces personalized campaign assets through a set of skills. Two real operators, two completely different situations, two completely different outputs.

The system is designed to compound. Brand positioning and skills are permanent and evolve slowly. Each conference campaign gets its own folder with operators, engagement data, and generated outputs. After three cycles, the targeting is sharper, the creative is better, and you know your CAC per tier.

Each skill reads from these layers and produces output that reflects the specific combination of inputs. Same skill, different operator, different output, because the inputs are different.

Tier Logic

Operators are classified into tiers based on rules, not a point system. Any single qualifying criterion is enough to trigger a tier.

TierCriteria (any one qualifies)What They Get
Tier 120+ communities, OR tech-forward posture, OR competitive displacement opportunity, OR existing sales contactEvery skill, full contact-level personalization
Tier 25-19 communities, OR some tech adoption signals, OR campaign engagement without sales contactPre-event emails and one-pager, persona-matched
Tier 3Under 5 communities, OR no actionable intelligenceDefault landing page and standard sequence

Override Flags

  • Stalled deal: HubSpot shows stalled + 30 days inactive. Triggers different re-engagement approach regardless of tier.
  • Limited intelligence: No researched profile exists. Caps tier at 2 until a profile is built.
  • Engagement without relationship: Someone at the company is clicking ads or visiting the site, but there's no sales record. Flag for pipeline addition.

These are rules-based criteria. With real pipeline data across multiple cycles, the tier logic gets calibrated against actual conversions: which criteria predicted closed deals. That calibration turns rules into a weighted model over time.

Skills

Score and Tier

Rules-based tier assignment with override flags for stalled deals, limited intelligence, and engagement without a sales relationship. Outputs tier, rationale, recommended skill sequence, and CRM actions.

Runs first

Pre-Event Sequence

3 emails per contact. Four paths: Cold, Warm, Stalled, Limited Intelligence. Proof point rotation across contacts. Engagement-informed divergence when one contact is hot and another is cold.

Per operator

Post-Event Follow-Up

Cross-references engagement signals across 4 channels. Scores each contact's engagement depth. Classifies as Champion, Researcher, Connector, Blocker, or Ghost. Ghosts get no follow-up.

Per operator

One-Pager Brief

Sales leave-behind tailored to the operator. Three intelligence levels (full, partial, minimal). Proof point deduplication against emails. Competitive displacement and EHR integration sections when applicable.

Per operator

Landing Page Copy

Conference landing page. Default version for all attendees, or operator-specific variant for targeted ads. Proof points selected by acuity mix.

Per campaign

Signal Synthesis

Cross-operator intelligence brief. Creative performance, email analysis, website behavior categorization, champion/blocker identification, pipeline health, budget reallocation recommendations.

Per campaign

Production Roadmap

Phase 1: Integration Layer

Replace simulated data with live API pulls. HubSpot API for sales data, Meta Ads API for retargeting metrics, LinkedIn Campaign Manager for audience engagement, email platform for open/click tracking, GA4 for website sessions. Each source normalizes into the existing JSON schemas. The skills don't change. The data layer becomes real.

Phase 2: Automation Layer

Replace manual skill invocation with a scheduled pipeline. Weekly data pulls trigger signal synthesis. Campaign timeline triggers skills automatically (T-21 days: score and tier, T-14: pre-event emails, T+2: post-event followup). All generated content goes to a human review queue before sending. The system drafts. Humans approve.

Phase 3: Feedback Layer

Actual campaign performance data flows back into the system. Which emails were opened, which CTAs converted, which deals advanced. Over three cycles, this enables proof point selection based on historical performance, subject line testing, and persona response pattern learning. Skill updates are tracked in git. The git history becomes institutional memory.

This prototype uses real, verified operator research and simulated engagement data. All simulated files are marked. The logic layer works independently of the integration layer by design, so the thinking can be evaluated before the pipes are built.
